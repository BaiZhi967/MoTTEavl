# M2 开工交接 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 本文是已批准详细计划的开工补充与开发提示词，不替代原工作包。

**Goal:** 在 M1 修复代码基线上交付 M2 全部开发范围，按层级记录真实验收证据。

**Architecture:** 复用现有运行、证据、存储和评分主链路，增加 job-based 执行。C-Eval 与 CMMLU 共用外部 Job 基础；比较和门禁复用 M6-Lite 公共实现。

**Tech Stack:** Python 3.12 / uv / FastAPI / React / Vite / pnpm / SQLite / PostgreSQL；外部 Runner 使用固定的独立环境。

**Spec:** [M2 原需求](../../roadmap/M2-llm-benchmarks-and-ceval.md)、[M2 详细任务](2026-09-19-m1-m7/M2.md)、[M6 Lite 责任任务](2026-09-19-m1-m7/M6.md)。

## Global Constraints

- 保留 M2-G01～G17、M2-A01～A15、M2-T01～T11 及原需求非编号约束。
- 本轮只完成代码复审与开发交接，不启动 M2 实现或真实模型调用。
- 开工必须包含 M1 修复基线 e9edb80；计划旧基线用于历史追溯，不用于覆盖当前代码。
- M1 代码复审通过不等于 M1-Supported 或全部资源隔离验收已通过。
- CMMLU 在 C-Eval 首批链路后独立交付，未验证状态不能继承 C-Eval。
- M6-Lite 的 T01/T02/T03 提前实施；不创建 C-Eval 专用 Gate，也不扩展 M6-Full。
- 新文件路径和接口先对照当前实现；详细步骤沿用链接中的原工作包，不重复定义。
- 不清理已有未跟踪 var/，不自动合并主干，不触发未授权真实模型/生产操作。

## Review Focus

- T02/T03：启动后句柄落库失败、结算失败伴随迟到输出；一个启动身份，未知副作用隔离。
- T02/T06：路径父链替换、半写文件、超大输入；创建/读取/清理都不能越界。
- T03/T06：重复 key 内容冲突、只有聚合、部分输出；事务导入且 selected Case 不消失。
- T05/T06/T07：中文密钥、gold、身份字段脱敏、共享期限；公开安全不破坏冻结评分输入。
- M6-Lite/T08/T09：缺覆盖、费用未知、跨 Run/Case/pass 的迟到成功或失败；不误显示或误放行。

以上重点作为各原工作包反例的追加检查，不能只用最终 happy-path 集成替代。

三、必须保持的工程边界
- 复用 RunDispatcher、执行权、CAS、CaseAttempt、needs_review、Artifact、MetricResult、ScoreSet 和 ScoringPass。显式区分 sample/job 模式，一次 job-based Run 只启动一个 Job，不能逐题重启 Runner。
- start 前持久化意图和唯一 launch_token；PID 必须伴随启动身份/资源所有权。恢复时能确认原 Job 就只观察和采集，无法确认则 needs_review，不自动重新执行。
- 主流程独占持久状态变更。取消、超时、隔离之后，迟到线程/回调不得修改执行结论；允许的迟到审计另行记录。结算失败不能当作普通可恢复工具错误。
- 原始 Runner 输出先冻结为受控 Artifact，再解析。job_id + source_record_key + parser_version 同键同内容为 no-op，同键不同内容为 conflict；结果与 checkpoint 事务提交。保留每个 selected Case 的 disposition。
- 数据 revision、文件 hash、split、许可、选样顺序、Profile、few-shot、prompt/hash、extractor/scorer、Runner 版本和环境 digest 都必须真实固定。来源不明只标 user-supplied；无 gold 不编造准确率。
- few-shot 仅用合法分区，目标样本 gold/隐藏规则不得进入 subject 输入。保留 native.* 与 diagnostic.*，不拿诊断重算覆盖原生分数，不把 smoke/subset 冒充完整官方结果。
- 旧 Parser 迁移以原需求固定的旧提交 b661bcdf83e1c3dfb8d6062ee78817d249e86a4c 为依据，记录来源、许可、保留/改变语义与逐项差异。不能用自己写的新解析器冒充旧实现对照。
- OpenCompass 运行在独立固定环境；API 只做校验/提交/查询。禁止执行用户任意 Python 配置，不往 API 环境塞完整 Runner 依赖，不静默升级 latest。
- 凭据按引用在执行时解析，不进入持久配置、命令行、日志或公开响应。展示脱敏不得修改身份字段或冻结评分原文；覆盖中文相邻密钥、所有公共接口和事件流。
- 路径操作使用受控目录与可靠的相对目录描述符边界，覆盖 symlink 替换竞态；限制 JSON/CSV/压缩输入大小和执行期限。循环处理多条记录时共享剩余总预算，不能每条重新领满额度。
- 保留 Provider/Runner/平台 retry 的不同语义；费用、usage、模型身份可见度未知时如实标记 unknown。
- 比较固定 Run+ScoringPass，逐指标判断可比性。缺覆盖、unknown cost、NaN/空分母不能通过对应硬门禁。GET/report/compare/gate 不产生模型或 Judge 调用。
- UI 使用统一状态、token、Radix 和 Phosphor；跨 Run/Case/pass 的缓存、加载、成功和失败响应都需要身份保护。
- migration 接在实际当前 head 后，不改写旧 migration；保持旧 Direct LLM、GSM8K、Replay、M1 Agent 与历史报告兼容。
