# M4 Pi / External Harness 开发交接计划

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans 按工作包实施。本文与原逐包计划共同构成完整交接；所有实现步骤保持未勾选。

**Goal:** 实现真实 Pi、Claude CLI、Codex CLI 的受控任务执行、证据、评分、取消与恢复；覆盖 M4-G01–G18、T01–T11、A01–A15，保留交互和 Inspect 独立交付。

**Architecture:** 在现有 ExecutionBackendSpec / ExecutionHandle / Dispatcher / RunService 上注册 sample backend；每个 CaseAttempt 独立 session/workspace。运行器只产出事件和 AgentResult，平台保有持久化与 ScoringPass 主权。命令复用 RunCommand；Inspect 只读导入不进入 Dispatcher。

**Tech Stack:** 现有 uv Python/FastAPI/Pydantic、Node/pnpm Pi bridge、固定版本 CLI、React/Vite；SQLite/PostgreSQL/InMemory。上游确切版本在 T02 验证并锁定，不采用 latest。

**Spec:** [M4 全文](../../roadmap/M4-pi-and-external-harnesses.md)、[原逐包实施卡及完整覆盖表](2026-09-19-m1-m7/M4.md)、[全局约束](../../roadmap/README.md)。本文补充当前实现差距、接口决策、验证顺序，不替代或删减原要求。

**当前基线:** 主干 `a3cdfbe` 已包含 M3 第三轮修复；实际修复与验证见 [M3 修复记录](../../verification/M3-review-round3-fixes-2026-09-20.md)。M4 状态为 planned / implementation_not_run，不把 M3 离线门禁当成任何 M4 live 支持证据。

## Global Constraints

- 平台保持单用户、API-first 和既有 workspace；不引入第二个调度器、Provider、资源注册表或评分数据库。
- Run、CaseAttempt、session、operation、工具 call、command、评分 pass 各自有身份；队列重投递与断连不得重放可能已执行的任务。
- 已发布 RuntimeVersion/Profile 和冻结 Run 配置不可变。进程退出、任务完成、质量通过、清理完成分别记录。
- 不把安装成功、版本输出、fixture 或 SDK schema 接受当成真实执行支持。状态保留 installed / protocol_ready / execution_ready，支持证据另列级别与环境。
- 默认所有测试离线；真实 Provider、个人订阅、Docker 执行、活动 Worker 操作按明确授权范围执行。先完成离线工作与可操作 live 验收包；缺授权时保留未验证项，不删任务或假报支持。
- subprocess env allowlist 不是工具隔离。不能证明工具无法读取宿主秘密时，不承诺隔离；严格策略须拒绝该配置。
- UI 实施前读 AGENTS.md、apps/web/DESIGN.md 和项目指定技能；沿用 tokens / STATUS_META / Radix / Phosphor。API 契约变化同提交生成 OpenAPI 与 TS。
- 不实现 M5–M7 的完整功能；只输出 Skill 注入能力、model/tool control、intervention 等下游证据。

## Review Focus

- 公共 API/CLI 是否把已发布模型参数、原生配置、权限和预算真正送到执行消费者；不能只测 helper。
- 配置中的默认值、home、env_file、自动发现规则与实际进程环境是否一致，日志脱敏不等于任务拿不到秘密。
- 父进程退出后子工具仍写文件、进程 PID 被复用、Worker 重启、工具结果迟到，是否误清理/误复跑。
- 未返回模型或 usage 时是否错误填入请求值/零费用；缺终态事件是否因 exit=0 变成 succeeded。
- 队列取消与创建/采集失败是否保留完整计划 Case、Attempt、评分覆盖；跨 Run/session 事件是否提前隔离。
- command 的 HTTP 202、投递、上游 ack、执行完成是否混淆；旧批准能否授权新 tool request。

## 2. 固定技术决策与交接接口

1. batch 首版使用 `pi-agent@1`、`claude-cli@1`、`codex-cli@1`，execution_mode=sample；统一在 `runtime_backends.py` 注册/组装，执行细节分 runtime。交互用独立 version/transport，不修改历史 batch 的能力快照。
2. Pi 首选官方最小 agent SDK + 平台 Provider/ToolRegistry 公开注入。如果固定版本无法提供该路径，记录实验并改为 runner-configured，严格策略拒绝不可强制能力；不声称 platform-controlled。
3. Claude 选择固定版本的 batch 结构化流；Codex batch 选择 exec JSONL。T02 通过所选二进制 help、零费用协议夹具、原生配置验证来冻结 argv，不仅引用在线文档。
4. M4-C 选 Codex app-server 作为唯一交互 transport，独立注册 `codex-app-server@1`。T02 同时验证其协议和所需权限；若固定版缺能力，明确能力阻塞，继续完成无依赖工作，不悄悄换后端。
5. M4-D 纳入完整交付：固定一个真实 Inspect 日志 schema，导入样本和评分来源；不支持的新 schema 明确拒绝。原始归档只读，不运行 task、插件、pickle 或日志里命令。

| 契约/接口 | 拟落位与规则 |
|---|---|
| RuntimeDefinition/RuntimeVersion | `packages/contracts/motte_contracts/runtime.py`；id/version/kind/transport/upstream_version/adapter_version/parser_version/config_schema/supported_modes/model_control/tool_control/evidence_capabilities；严格类型、字段 allowlist |
| RuntimeProfile | 同文件；runtime_ref/native settings/workspace 来源/tool-network-approval policies/budgets/credential_refs；与实际执行编译结果同 hash，无秘密原文 |
| RuntimeSession | `packages/harness-runtime/motte_harness/session.py`；run/case/attempt/session/operation/start_token、config_hash、进程创建身份、checkpoint、terminal/cleanup 证据；CAS 持久化走现有 storage |
| 标准事件 | `motte_agent/protocol.py` 与 `motte_harness/protocol.py` 共享 envelope 语义：run/case/session/operation、source_id/source_seq/platform_seq、type、parser_version、payload_ref、coverage；身份错误在写库前拒绝 |
| Backend | `runtime_backends.py` 产 ExecutionHandle(invoke, attach, capabilities)；attach 接 InvocationRecord/EventSink/取消探测；业务结果接既有 AgentResult→Observation→ScoringPass |
| ConfigSnapshot | 记录请求配置、有效配置、二进制/hash、工作区 revision/dirty patch hash、规则/Skill/MCP/plugin 清单/hash、环境变量名、模型控制、权限执行主体；不能用请求值替代 observed |
| 命令 | 沿用 RunCommand.id/type/status，扩展 session/case/expiry/expected_session_revision/dedupe_key/request_hash；状态新增 rejected/expired/delivery_unknown 并兼容历史 failed |
| 原始日志导入 | 原始 hash + source/schema/parser version + 源 sample id 去重；同 hash 重导幂等，同身份异内容产生冲突；原生评分标 imported，平台重评另建 pass |

工具权限取资源、Run policy、runtime 可强制能力的交集。平台原生能力声明不能给工具授权。实际模型控制为 platform-controlled / runner-configured / externally-managed；strict require_match 证据不足必须按既有政策阻断，不能宣称可比。
