## Review Focus

- Scenario 当前必填 model 与原生认证 CLI 不匹配，T01 按 backend 验证。

## 1. 进入条件与分批安排

M1 全部 runtime/工具/证据接口；不依赖 Harbor 完成。

1. T01 → T02 → T03 → T04：Runtime 契约与 Pi 真 SDK。
2. T05 → T06 → T07 → T08 → T09：公共 supervisor 与两个 batch 后端、分后端支持验收。
3. T10：单后端交互 consumer；T11：Inspect 只读导入，分别评审、不改变 batch 退出门。

工程量估算 33–53 人日，包含实现、focused 回归和工作包 review，不包含等待许可证据、预算批准、外部环境与人工标注。它是初步排期范围，不是交付承诺；完成前两包后按实际吞吐重新估计。每个工作包一般拆 1–3 个可独立测试的提交，固定“一项主功能 + 一项验证”的在制品限制。

## 2. 工作包实施卡

接口字段、错误与不变量以本阶段 Spec 第 3 节及后续契约章节为输入；下方“消费 → 产出”明确交接边界。远期 Python 私有函数签名不预先锁死；实际开工时先核对已合入公共契约并补可执行单测，再实现。每张卡都须完成所有步骤，不能用最后一个集成测试替代前置反例。
