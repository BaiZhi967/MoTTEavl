## Review Focus

- 正确终态掩盖缺确认或重复副作用，T04 验证过程和计数。
- 纯指令被强制 entrypoint，T06 分 kind 演进而非迁成可执行程序。
- Skill 扩权或 A/B 状态串扰，T07/T08 权限交集与独立资源。
- Judge rescore 在 API 进程收费或替换有效 pass，T09 验证 Worker 所有权和发布条件。
- 合成标签冒充人工校准，T10 检查来源、至少30个人工样本和 rubric 版本。

## 1. 进入条件与分批安排

M1 全链路、M6-Lite；M4 外部 runtime 是可选目标。

1. T01 → T02 → T03 → T04 → T05：DSL、Fixture、Target、断言与场景后端。
2. T06 → T07 → T08：Skill 版本/注入/fixture 与三组对照。
3. T09 → T10 → T11 → T12：Judge 作业/校准、统一入口与七类流程验收。

工程量估算 33–54 人日，包含实现、focused 回归和工作包 review，不包含等待许可证据、预算批准、外部环境与人工标注。它是初步排期范围，不是交付承诺；完成前两包后按实际吞吐重新估计。每个工作包一般拆 1–3 个可独立测试的提交，固定“一项主功能 + 一项验证”的在制品限制。

## 2. 工作包实施卡

接口字段、错误与不变量以本阶段 Spec 第 3 节及后续契约章节为输入；下方“消费 → 产出”明确交接边界。远期 Python 私有函数签名不预先锁死；实际开工时先核对已合入公共契约并补可执行单测，再实现。每张卡都须完成所有步骤，不能用最后一个集成测试替代前置反例。
