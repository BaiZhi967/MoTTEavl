- “保持单用户、API-first、Python/FastAPI/Pydantic、React/Vite、现有 uv/pnpm workspace。”
- “Run、Case、Trial、传输重试、操作员 retry 和评分 pass 的身份分开。”
- “已发布资源与终态评分不可覆盖。”
- “MetricResult 是评估视图，持久化仍进入既有 ScoreSet。”
- “默认测试不使用真实模型或个人订阅。” subject、Judge、Harness 的 live 分别授权和计量。
- 遵守 [AGENTS.md](../../../../AGENTS.md) 与 [DESIGN.md](../../../../apps/web/DESIGN.md)。运行状态由 STATUS_META 派生；Radix / Phosphor Icon 后缀；新 token 先登记 DESIGN.md 再加 :root。
- 各任务的路径是仓库相对路径；“修改”表示当前存在，“新增计划”表示尚不存在，最终落位在开工时重新核对。新 schema 沿实际 migration head 追加，不预占 revision。
- 下文测试命令为将来执行步骤，缺文件/ImportError 只说明尚未实现，不能作为业务红灯或通过记录。先写可收集的断言测试，红灯必须对应列出的行为缺口。

## Review Focus

- CaseAttempt 当前 Case 级排他阻止多 Trial，T02 扩展冲突域而非覆盖 Case。
- reward=0 被 truthy 判断当成缺失，T04 覆盖零/缺失/畸形。
- Verifier 失败被过滤提高通过率，T08 同时报有效率与计划覆盖。
- 取消误删共享容器，T07 以启动身份/owner token 校验。
- 安全隔离改变官方环境却沿用 Profile，T05 强制产生新 fingerprint。

## 1. 进入条件与分批安排

M2-T01/T02/T03，M1 多指标存储；M6-T02 覆盖语义。

1. T01 → T02：任务身份和 Trial 存储。
2. T03 → T04 → T05 → T06：配置、纯解析、环境预检与实际 Job。
3. T07 → T08 → T09 → T10：清理恢复、评分、用户入口与实际校准。

工程量估算 26–41 人日，包含实现、focused 回归和工作包 review，不包含等待许可证据、预算批准、外部环境与人工标注。它是初步排期范围，不是交付承诺；完成前两包后按实际吞吐重新估计。每个工作包一般拆 1–3 个可独立测试的提交，固定“一项主功能 + 一项验证”的在制品限制。

## 2. 工作包实施卡

接口字段、错误与不变量以本阶段 Spec 第 3 节及后续契约章节为输入；下方“消费 → 产出”明确交接边界。远期 Python 私有函数签名不预先锁死；实际开工时先核对已合入公共契约并补可执行单测，再实现。每张卡都须完成所有步骤，不能用最后一个集成测试替代前置反例。
